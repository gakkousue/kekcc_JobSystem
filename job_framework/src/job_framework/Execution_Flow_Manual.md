# Job Framework 実行フローと使用方法マニュアル

本ドキュメントでは、`job_framework` 内のそれぞれの主要クラス（ファイル）について、内部でどのような処理順序（実行フロー）で動いているかと、実際の使い方（サブクラス化の方法や実装すべきメソッド）を詳細に説明します。

---

## 1. `batch_job.py` (`BatchJob` クラス)

すべてのジョブクラスの最上位となる抽象基底クラスです。コマンドライン引数の解析と実行の基本インターフェースを定義しています。

### 実行フロー
1. スクリプトとして直接実行された場合、`main()` メソッドが起点となります。
2. `get_parser()` を呼び出し、ジョブに必要な引数を定義した `ArgumentParser`（または `InteractiveArgumentParser`）を取得します。
3. `parse_args()` を使用して引数を解析します。ターミナル実行（対話環境）の場合は、オプションの確認プロンプトが表示されます。
4. 解析が完了した引数 (`args`) を用いて、`execute(args)` が呼び出され、メイン処理が開始されます。
5. エラーが発生した場合はキャッチして標準エラー出力に表示し、終了します。

### 実際の使い方
直接このクラスを継承することは少ないですが、ディレクトリ作成などを伴わない非常にシンプルな独立単体ジョブを作る場合に継承します。
- **実装すべきメソッド**:
  - `get_parser(self)`: このジョブが受け取る引数を定義し、パーサーを返します。
  - `execute(self, args)`: ジョブの実際のロジックをここに記述します。

## 2. `structured_job_base.py` (`StructuredJobBase` クラス)

`BatchJob` を継承し、ジョブ実行時の「出力ディレクトリの自動生成と管理」のフローを追加したクラスです。

### 実行フロー
1. `main()` -> `execute(args)` の順で呼び出されます（`BatchJob` と同じ）。
2. `execute(args)` 内で、引数の `base_output_dir` と `outputdir` を結合し、最終的な出力先パスを決定します。
3. `_setup_output_dirs()` を呼び出し、必要なディレクトリパスの辞書（カテゴリ名とパスのペア）を取得します。
   - ここで、ユーザーが定義した `setup_output_dirs()` も連鎖して呼び出されます。
4. `outputdir` 本体と、辞書で定義された全てのサブディレクトリがシステム上に自動で作成されます。
5. ディレクトリ群 (`custom_output_dirs`) を引数として、実際のメインロジックである `run_structured_job(args, custom_output_dirs)` に委譲します。

### 実際の使い方
特定のディレクトリ構造を構築しながら処理を行いたいジョブで継承します。
- **実装すべきメソッド**:
  - `run_structured_job(self, args, custom_output_dirs)`: 実際の処理を記述します。`custom_output_dirs` には作成されたディレクトリの辞書が渡されます。
- **オプションでオーバーライドするメソッド**:
  - `setup_output_dirs(self, args, outputdir)`: `{'カテゴリ名': 'パス'}` という辞書を返すように実装し、独自に必要なサブディレクトリを定義します。
  - `add_args(self, parser)`: 追加の独自引数を定義したい場合に使用します。

## 3. `list_file_job_base.py` (`ListFileJobBase` クラス)

`StructuredJobBase` を継承し、入力一覧のテキストファイル（`.list` ファイル。各行に処理対象のファイル名が記載されているもの）を受け取って、各対象に対してループ処理を行うための基底クラスです。

### 実行フロー
1. `execute(args)` を経てディレクトリ作成が行われた後、`run_structured_job` が呼び出されます。
2. パスの解決を行います（`use_listfile_dir` や `base_list_base_dir_dir` 引数の処理）。
3. 指定された `.list` ファイルを読み込み、処理を開始する行番号 (`nstart`) や処理件数 (`count`) に従って対象ファイルのリストを抽出します。
4. 抽出された各ファイルが実際に物理的に存在するかを全て事前にチェックします（一つでも不足があればエラーを出して停止します）。
5. 存在するファイルリストに対してループを回し、1ファイルずつ `process_file()` メソッドに渡して個別の処理を実行します。
6. すべてのファイルの処理が終わった後、`process_file()` が返した結果をカテゴリごとにまとめ、出力ディレクトリに結果の `.list` ファイルを自動作成します。

### 実際の使い方
複数のファイルを一括で処理するバッチスクリプトを作成する場合に継承します。
- **実装すべきメソッド**:
  - `process_file(self, inputfile_path, output_basename, args, output_dirs)`: 1ファイルごとの処理を記述します。
    - 戻り値として `{'カテゴリ名': '次に引き継ぐ文字列(出力ファイル名など)'}` という辞書を返す必要があります。これが結合されて結果 `.list` ファイルになります。

## 4. `lsf_job.py` (`LSFJob` クラス)

`ListFileJobBase` を継承し、ループ内の各個別処理を LSF (Load Sharing Facility) のジョブ管理システム (`bsub`) へ投入するフローを追加したクラスです。

### 実行フロー
1. `ListFileJobBase` と同様にリストファイルを読み込み、ループ処理を開始します。
2. ループ内で `process_file()` が呼ばれると、ユーザーが実装した `generate_command()` が呼び出され、実行したい「コマンド文字列」を取得します。
3. `logs/sh/`, `logs/log/`, `logs/bsublog/` という必須ディレクトリが自動生成されており、その中に「対象ディレクトリに移動し、指定されたコマンドを実行して標準出力をログに落とす」という内容のシェルスクリプト (`.sh`) が動的に生成されます。
4. `subprocess.run` を使用して `bsub -q [キュー名] [シェルスクリプト]` コマンドを実行し、生成したシェルスクリプトを LSF に投入します。
5. 成功・失敗の出力をコンソールに表示しつつ、リストエントリ情報を返して次のファイルの処理に進みます。

### 実際の使い方
クラスタで分散処理を行うジョブを作る場合に継承します。
- **実装すべきメソッド**:
  - `generate_command(self, inputfile_path, output_basename, args, output_dirs)`
    - 戻り値として、`(実行するコマンドの文字列, リストエントリの辞書)` というタプルを返します。
- コマンドライン実行時に `-q` または `--queue` で投入先キューを指定可能です（デフォルトは `s`）。

---

## 5. `local_job.py` (`LocalJob` クラス)

`ListFileJobBase` を継承し、LSF等のジョブスケジューラを使わずにローカル環境で直接ループ処理を実行する機能を提供するクラスです。

### 実行フロー
1. 他の List 系クラスと同様にリストファイルをパースして対象を絞り込みます。
2. ループ内で呼ばれる `process_file()` 内で、標準出力と標準エラー出力 (`os.sys.stdout`, `os.sys.stderr`) が、そのファイル専用のログファイルに向くように一時的にリダイレクトされます（`logs/log/` 配下に保存）。
3. リダイレクトされた状態で、ユーザーが実装した `run_local()` が呼び出され、実際の処理がローカルプロセス上で同期的に実行されます。
4. 処理が終わると出力をターミナルに戻し、次のファイルへ移行します。

### 実際の使い方
テスト用途や、LSF環境がない環境で同様の複数ファイル処理を走らせるためのジョブに継承します。
- **実装すべきメソッド**:
  - `run_local(self, inputfile_path, output_basename, args, output_dirs)`
    - 引数や戻り値の形は、通常 `process_file` と同じです。`{'カテゴリ名': '出力文字列'}` の辞書を返します。

## 6. `batch_run.py` (`BatchRunnerJob` クラス)

このシステム全体を統括し、複数の「ジョブコマンド」を一つの JSON 定義ファイルから一括で連続実行するための特殊なランナークラスです。これ自身も `StructuredJobBase` のサブクラスとして実装されています。

### 実行フロー
1. トップレベル (`main()`) から呼ばれると、環境変数の再帰深度 (`BATCH_RUN_DEPTH`) を確認します。再帰深度 0 の場合、全ての標準出力・エラー出力を `batch_run.log` ファイルとターミナル両方へ出力する状態（`JobDualStream`）に設定します。
2. JSON 設定ファイルを解析し、指定された `target_module` または `target_script` と `target_class` を用いて、外部から動的に対象の Python モジュールをロードし、ジョブクラスのインスタンスを生成します。
3. **Phase 1 (事前検証)**: JSON内の `jobs` リストを一つずつ取り出し、結合したパラメータ辞書を用いて、ロードしたターゲットクラスのパーサー（`InteractiveArgumentParser`）でパース可能か（必須チェックや型バリデーションに失敗しないか）をテストします。一つでもエラーがあれば実行せずに中止します。
4. **Phase 2 (ジョブ実行)**: 検証をパスしたタスク群を順番に実行します。
5. 各ジョブ実行時、そのジョブ専用の個別ログファイル内にさらに出力をリダイレクトしつつ、ターミナルにはインデントを付けた形で（階層が解るようにして）出力をリアルタイム表示・保存します。
6. `job_instance.execute(args_namespace)` を呼び出し、実際のジョブクラスの処理を代行実行します。エラーが起きた場合はスタックトレースをログに残して次のジョブに進みます（または停止します）。

### 実際の使い方
開発者が新しくクラスを作るのではなく、ユーザーがジョブシステムを起動するためのユーティリティとして使います。
- **コマンドラインでの使用**:
  ```bash
  python -m job_framework.batch_run config.json [outputdir]
  ```

  ```

  **`batch_run` 実行において常に利用可能な主要キー（変数）**:
  
  【JSONのルート階層】
  - `target_module` (string): 実行対象クラスが含まれるモジュールのインポートパス（例: `job_modules.run_marlin.run_marlin`）。優先して参照されます。
  - `target_script` (string): `target_module` の代わりに、実行対象クラスが含まれるPythonスクリプトへのパス（`.py`）を直接指定します。
  - `target_class` (string): 呼び出したいジョブクラスの名前（例: `MarlinJob`）。
  - `common_settings` (dict): `jobs` に記載する各ジョブで共通して使われる引数の設定値（辞書）です。
  - `jobs` (list of dicts): 実際に実行される個別のジョブ設定のリストです。この中に書かれた値は `common_settings` とマージされて最終的な引数になります。

  【`common_settings` および `jobs` の各要素内でシステムが解釈する特別なキー】
  - `comment` (string, 任意): 実行時のコンソールやログに「ジョブ 1/N を開始します: {comment}」の形で表示されるタイトルや説明です。
  - `outputdir` (string): ジョブ出力先ディレクトリ。`batch_run` はこの値を読み取り、各ジョブ個別のログ（標準出力）をこのディレクトリ内に自動で振り分けて保存します。
  - `base_output_dir` (string): `outputdir` が相対パスで指定されている場合に基準となるディレクトリパスです。

- **JSONの書き方**:
  上記を踏まえたJSONファイルの記述例です。ジョブ特有のパラメーターはそのジョブのクラス仕様に従って自由に追加できますが、以下は `batch_run` が解釈する基礎的なキーだけで構成した骨組みです。

  ```json
  {
    "target_module": "job_modules.run_marlin.run_marlin",
    "target_class": "MarlinJob",
    "common_settings": {
      "base_output_dir": "/path/to/base/dir"
    },
    "jobs": [
      {
        "outputdir": "job1_out",
        "comment": "1つ目のジョブを実行"
      },
      {
        "outputdir": "job2_out",
        "comment": "2つ目のジョブを実行"
      }
    ]
  }
  ```
